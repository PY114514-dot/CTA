# 产品净值研究与 FOF 工作台：系统总览

> 更新：2026-08-21。本文汇总产品范围、数据规则、功能、方法边界、运行方式和术语；取代此前分散的需求、架构、调研、参数与自审文档。

## 1. 系统定位

这是一个个人使用的私募产品研究工具。它把原始材料、净值和因子数据整理为可复核的数据对象，用确定性程序完成业绩、风险、归因、排名和组合研究；LLM 只负责解释已计算的结果和生成报告，不参与数值计算或审核。

系统输出是研究辅助，不是投资建议，不推断真实持仓、仓位、交易成本、管理人技能或未来表现。

## 2. 当前数据与工作流

### 数据入口

- CSV、XLSX、PDF、DOCX、PPTX、图片和文本材料；图片/文档中的净值必须进入候选和人工复核流程。
- 期货周频 SQLite：验证 `product_info`、`weekly_return_raw`、`nav_weekly_snapshot` 三张表后直接导入结构化净值。此类净值标为直接来源，不适用图片曲线与披露数字冲突校验。
- 因子数据：版本化公开因子、经审核的期限结构输入，以及南华商品指数。

### 数据状态

1. 原始材料与候选净值保留来源；
2. 产品身份确认、净值人工审核后才进入研究；
3. 所有正式计算只读取已确认产品的已审核净值；
4. 归因、排名和报告可以保存分析结果存档，记录净值版本、因子版本、模型版本、截止日和参数。

SQLite 直接净值当前可进入研究，但仍保留产品名称、策略和来源的人工修订入口。

## 3. 产品库与研究界面

### 产品库

- 分页加载，避免大产品池造成前端卡顿；
- 产品状态分为可研究、需复核和不可用；
- 详情展示净值曲线、同类高相关产品及低相关替代品；
- 名称标签按“产品名 + 已有策略”生成股票、量化、CTA、波动率、期权等初步标签。它们只用于筛选，不覆盖人工确认的策略。

### 研究筛选

可按名称、管理人、策略、CODEX 排名、质量分、收益、波动、夏普、回撤、名称标签和波动分层筛选。

波动分层以当前产品池年化波动的三等分生成“相对低波 / 中波 / 相对高波”，只能用于池内比较。

## 4. 确定性分析能力

### 业绩与风险

- 净值、区间收益、年化收益、年化波动、夏普、最大回撤、卡玛、回撤持续期和最差 5% 平均亏损；
- 产品和市场数据按真实日期与频率对齐，日/周/月年化因子分别为 252/52/12；
- 不足样本、频率不一致或来源不完整会明确降级，不静默补值。

### 收益型风格归因

归因描述产品收益与公开因子的历史统计关系，不能视为持仓归因。

1. **基础归因**：多因子回归、关联系数、显著性、收益贡献、统计风险贡献、R²、样本外 R² 和残差诊断；
2. **关联变化**：滚动窗口和动态关联系数，用于识别风格是否稳定；
3. **市场环境表现**：以滞后市场信息划分常态、压力和震荡反复环境，比较条件收益、相关性与样本量；
4. **补充检验**：预登记的动量 × 波动率交互，和基础模型做连续样本外比较。

样本外 R² 小于零表示该模型在测试段的误差高于历史均值基准；它不表示产品无价值，而是当前因子模型不适合用于稳定解释或预测该产品。此时页面必须拒绝强化未解释收益、贡献或风险结论。

### CODEX 排名与产品评分

- CODEX 排名是只读的横截面研究排序，包含收益质量、风险调整、趋势/状态适应、尾部表现和稳健性；不是配置建议。
- 全量周频产品导入后自动刷新排名；研究筛选始终使用覆盖产品最多的排名快照，避免单产品临时排名覆盖全量结果。
- 产品质量分和给定组合下的配置价值是两个问题：没有明确组合及权重时，不生成配置分或自动权重。

### 组合研究

组合风险地图读取已审核净值，比较相关性、回撤、因子重合与边际风险。系统不自动下单、不写入实际配置。

## 5. 方法边界与关键术语

| 界面术语 | 含义 | 不代表 |
| --- | --- | --- |
| 关联系数 | 产品收益与公开因子收益的统计关系 | 真实仓位或方向 |
| 收益贡献 | 因子在模型内解释的历史收益部分 | 实际 P&L 来源 |
| 统计风险贡献 | 因子及其协方差在模型内解释的波动部分 | 风险预算或仓位 |
| 未解释收益候选 | 当前因子模型未解释的收益部分 | 管理人能力或可投资 Alpha |
| 样本外 R² | 用过去训练、对未来测试段的解释/预测检验 | 未来收益保证 |
| 分析结果存档 | 固定当时数据与参数、可复核的历史结果 | 实时最新结果 |
| 名称标签 | 根据名称的初步分类 | 人工确认策略 |

LASSO、OLS、HAC 等方法名会在需要说明统计方法的高级页面保留；页面优先展示其研究含义。

## 6. 架构与运行

- 前端：React、TypeScript、Vite、Ant Design、ECharts；
- 后端：FastAPI、SQLAlchemy、pandas、NumPy、SciPy、statsmodels、scikit-learn、OpenCV；
- 存储：本地 SQLite 与文件系统，数据库迁移由 Alembic 管理；多人写入或生产部署再迁移 PostgreSQL/对象存储；
- 启动：项目根目录运行 `python start.py`，前端为 `http://127.0.0.1:5275`，API 为 `http://127.0.0.1:8103/docs`；
- 质量检查：`scripts/verify.ps1`，或至少执行后端相关测试与 `cd frontend; npx tsc -b`。

LLM 可选使用 OpenAI 兼容接口。令牌只放入后端环境变量或应用设置，不能写入仓库或前端配置。

## 7. 当前结论与下一步

当前系统已经具备结构化 SQLite 导入、全量产品筛选、自动 CODEX 排名、单产品四阶段归因和组合研究入口。主要研究短板不是再增加一套通用模型，而是让不同类型产品使用适合的因子集，并以严格样本外验证决定是否升级结论。

具体实现顺序、验收条件和拒绝规则见《[下一版开发计划：归因可解释性](下一版开发计划-归因可解释性.md)》。
