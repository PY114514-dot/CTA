# 中国商品 CTA Carry：历史期限结构数据源调查

更新：2026-08-24。范围是为本项目补齐 2016 年以来的**真实期限结构 Carry**原始输入；不把主力连续价格、南华商品指数或短长收益差冒充为 Carry。

## 结论

能覆盖 2016 年以来且可复核的最低成本方案，是逐交易日保存三家商品交易所公开的日行情/合约资料，再在本地按品种选取近月与远月合约。数据来自交易所，并不依赖 AKShare；AKShare 可以保留为抓取适配器或交叉校验，但不应是唯一来源。

目前不存在一个已经确认“免费、稳定、允许无限历史批量再分发”的公共 API，能一口气提供所有中国期货合约的完整近远月结算价。公开网页可访问不等于获得再分发或商用许可；下载前和入库时都应保留交易所页面、下载时间、查询日期和原始文件，并按各站点的数据/网站条款复核用途。

## 推荐优先级

| 优先级 | 来源 | 能拿到什么 | 对 Carry 的作用 | 限制 |
| --- | --- | --- | --- | --- |
| 1 | 上期所、郑商所、大商所官方历史日行情 | 合约级日行情（应使用结算价；同时保存成交量、持仓量和合约代码） | 直接构造 2016 至今绝大部分商品的近远月期限结构 | 页面下载/接口格式会变；需逐日期回填并自行做合约到期日、流动性和异常值规则 |
| 2 | 广期所官方日行情 | 工业硅、碳酸锂等广期所品种的合约级数据 | 补 2022 年末开市以后的新交易所品种 | 不可能补足 2016 年以前，因为交易所当时尚未开市 |
| 3 | 中金所官方日行情 | 股指、国债等金融期货合约级数据 | 仅在 CTA 合同明确覆盖金融期货时，构造对应期限结构 | 不是商品 Carry；不应混入“商品 CTA Carry”横截面 |
| 4 | Tushare Pro | 有 token 的合约与日线 API | 便于批量拉取、与官方原始文件做覆盖/字段核对 | 访问由积分/权限控制，不能把它视为无条件免费或原始权威来源 |
| 5 | 新浪、东方财富等公开网页/API | 多为主力连续或单合约行情 | 仅作缺口诊断、临时下载或交叉校验 | 非稳定契约；连续合约不能构成真实近远月价差 |

### 交易所一手页面

1. [上期所历史数据](https://www.shfe.com.cn/data/dailydata/)：交易所的“每日行情”入口。上期所公开过按交易日返回的行情文件；实施时应以该页当前下载方式为准，而非把某个旧 URL 写死。
2. [大商所日行情](http://www.dce.com.cn/publicweb/quotesdata/dayQuotesCh.html)：可按交易日查询日行情；其页面属于交易所行情服务。
3. [郑商所每日行情](http://www.czce.com.cn/cn/jysj/lshq/H770319index_1.htm)：郑商所历史行情入口；历史文件路径随年份变动，应从入口页解析/下载。
4. [广期所行情数据](https://www.gfex.com.cn/gfex/rihq/hqsj_tjsj.shtml)：广期所日行情入口。广期所于 2022 年成立，不能要求其提供更早历史；[交易所概况](https://www.gfex.com.cn/gfex/gywm/jysjj.shtml) 可核对其成立背景。
5. [中金所成交持仓排名/日行情入口](http://www.cffex.com.cn/ccpm/)：金融期货需单独留在金融期货子池，避免和商品品种横截面混算。

上述页面是“字段与原始记录的权威来源”，但历史最早可取日、反爬频率、下载格式和数据使用权限都可能调整。因此导入前必须做一个只读探针：对每家交易所抽查 2016-01、2020-01、2024-01 各一个交易日，确认能否取得合约代码、结算价和成交/持仓字段，再决定回填范围；不可仅凭页面今天能打开就声称全历史已覆盖。

### Tushare：可用的便利层，但不是无条件免费源

[Tushare Pro 期货日线接口说明](https://tushare.pro/document/2?doc_id=138) 明确说明接口通过 `pro.fut_daily` 获取期货日线，字段含合约代码、交易日、收盘、结算、成交量和持仓量；[积分权限说明](https://tushare.pro/document/1?doc_id=290) 说明其数据接口受积分权限管理。它适合用 API 批量取数和验证缺口，但应：

- 用项目自己的 token，并在运行前检查当前账号的接口权限、单次/日限额和使用条款；
- 将交易所原始日行情作为可审计的主证据，Tushare 作为采集便利层或校验层；
- 不把“注册可用”描述为“免费且可无限制生产使用”。

## 正确的 Carry 输入和计算边界

每个品种、每个观测日应至少保存：`trade_date`、交易所、`contract_code`、`expiry_date`（或由合约规则可复算）、`settlement_price`、`volume`、`open_interest`、近月/远月选择规则和原始来源标识。近月应排除临近交割、停牌或无流动性的合约；远月应满足最小到期差。用结算价计算例如：

`carry_signal = -ln(far_settlement / near_settlement) / year_fraction(near_expiry, far_expiry)`

之后在同日商品横截面按该信号分组构造多空 Carry 组合，因子收益必须来自下一期各合约实际收益。价差水平（signal）与因子收益（return）不能混用。展期、涨跌停、合约缺失和品种上市/退市均须显式记录，不以 0 填充。

对本项目最小可行范围：先覆盖已有核心品种对应的上期所/郑商所/大商所合约，逐周取最后有效交易日；每周至少需要四个可用商品品种才能形成横截面，未达到门槛的周不生成 Carry。广期所和中金所随后作为扩展，而不是让它们阻塞 2016 年开始的商品样本。

## 南华商品指数：有用，但不能补 Carry

南华商品指数是“国内商品期货整体市场”的价格表现序列。项目中现有因子实现也将其定义为商品市场基准，而非交易信号或持仓还原（见 [NanhuaCommodityIndexFactor](../../backend/app/services/factor_library/nanhua.py)）。它可用于：

- 商品 CTA 对广义商品市场的方向 Beta；
- 市场状态/环境变量，例如高波动与低波动分段，或与趋势因子配合观察方向性暴露；
- 在完整 CTA 因子尚未覆盖时，作为单独标注为“市场基准”的参考序列。

它**不能**作为 Carry，因为单一指数没有同一品种的近月、远月合约价格和到期日，也没有横截面高/低 Carry 分组。即便指数编制中含有展期规则，其指数回报也不能识别为“期限结构 Carry 因子”。因此它可以提高市场状态解释的历史覆盖，却不能填补 2016--2023 年真实 Carry 的缺口；把它替代 Carry 会把方向性商品 Beta 错标为期限结构收益。

南华指数的指数编制、历史口径和再使用许可应向 [南华期货官网](https://www.nanhua.net/) 取得当期正式说明后写入数据 manifest；当前本地 SQLite 中的指数序列可以用于研究，但不是替代原始方法说明/许可的证据。

## 建议的落地顺序

1. 实现交易所日行情下载器的**只读探针**和原始文件归档，先验证三家老商品交易所的三个日期样本。
2. 针对每个交易日保留所有合约行；不要先压缩成主力连续价格，否则以后无法重选近远月。
3. 明确并冻结近远月、到期日、最小流动性、合约切换、缺失日和周度采样规则，生成版本化 manifest。
4. 回填 2016 至今，按年/交易所/品种输出覆盖率；只有覆盖率门槛通过的周才写入真实 Carry。
5. 用 Tushare 或现有 AKShare 结果逐样本核对，不一致时以交易所原始日行情为准并保留差异记录。
6. 继续把南华指数保留为 `commodity_market`/市场状态因子，名称和页面说明中不得称其为 Carry。

## 不推荐的捷径

- 用主力连续合约的 1 月减 6 月收益、南华商品指数、单品种价差或近月自身收益替代真实期限结构 Carry；它们可以是另一个代理或市场变量，但不是本因子合同中的 Carry。
- 将交易所当天公布的全部合约不经到期日和流动性筛选就取“代码最小/最大”作为近远月。
- 将历史不可得的日期补零，或因指数覆盖完整而把 Carry 标作完整覆盖。
