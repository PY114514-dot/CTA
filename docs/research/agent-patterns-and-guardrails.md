# Agent 范式与约束调研

调研日期：2026-08-26。范围：成熟框架的官方 GitHub README 与一手文档链接。

## 框架观察

| 框架 | 核心范式 | 对本项目可借鉴部分 |
|---|---|---|
| [LangGraph](https://github.com/langchain-ai/langgraph) | 显式状态图；长任务可恢复；短期与长期记忆；人工中断 | 配置研究应以状态机实现，而非开放式 ReAct 循环。每次状态转换可持久化和恢复。 |
| [OpenAI Agents SDK](https://github.com/openai/openai-agents-python) | Agent + 工具 + guardrails + handoff + session + tracing | 工具需有明确输入输出与权限；输入、输出和高风险动作都要经过 guardrail；完整轨迹可查看。 |
| [Microsoft AutoGen](https://github.com/microsoft/autogen) | 多 Agent 协作 | 官方 README 已标明维护模式，并建议新项目使用 Microsoft Agent Framework；当前不应把本项目建立在 AutoGen 上。 |
| [CrewAI](https://github.com/crewAIInc/crewAI) | Crew 分工或事件驱动 Flow | Flow 适合定义有序业务步骤；当前配置研究不需要先上多 Agent “Crew”。 |

## 适合本项目的范式

采用 **有界状态机 + 受限工具调用 + 人工确认**，而不是自由 ReAct 或多 Agent 群聊：

```text
理解需求 → 形成约束单 → 缺口追问 / 确认
→ 读取已复核产品库 → 确定性筛选与配置
→ 校验约束与数据质量 → 展示草案
→ 用户保存或修改 → 跟踪实际表现
```

LLM 仅可在“理解需求、追问缺口、解释已计算结果”三个状态参与；它不能选择未授权工具、访问未选择的单品资料，或生成、改写任何净值与权重。

## 必须约束

1. **工具白名单与参数校验**：不同状态只能调用预定义工具；所有产品 ID、产品数、权重、收益/风险阈值在工具边界校验。
2. **双重约束校验**：需求约束在解析后校验一次，优化结果返回前再校验一次；不满足时返回“不可行”，不得静默放宽。
3. **记忆分层**：会话工作记忆、用户明确偏好、不可变研究快照分离；不得把模型推测当作长期偏好。
4. **人工审批门**：保存的配置只能是研究草案；提交、批准、权重修改必须显式确认并留下版本与理由。
5. **全链路可观测**：保存计划、实际工具、参数摘要、耗时、失败、约束校验和结果快照；界面只展示可审计执行过程，不展示内部思维。
6. **停止条件与预算**：限定最大工具步数、单次耗时和 LLM 调用次数；失败、数据不足或约束冲突时停止并追问。

## 建议开发顺序

1. 先将配置 Agent 改为可恢复状态机，并增加“约束确认 / 不可行”状态。
2. 完成配置草案库：保存、版本、确定性评分、人工批准。
3. 增加运行详情页与评测集：覆盖产品数、回撤、无数据、矛盾约束等场景。
4. 最后再考虑单品研究子 Agent；暂不引入多 Agent 协作。
