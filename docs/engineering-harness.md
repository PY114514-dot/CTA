# Engineering Harness

本项目的 Harness Engineering 目标是让核心研究结论可复现、可回归、可审计。

## 一条命令的质量门槛

```powershell
.\scripts\verify.ps1
```

它会执行后端编译、后端测试和前端 TypeScript 检查；网络服务启动不属于该检查，以避免本机代理/Winsock 状态影响结果。

## 黄金样本

`backend/tests/fixtures/` 保存可公开、可再分发的最小样本。每增加一个报告解析器，必须同时增加：原始文本/脱敏 OCR 样本、期望结构化字段以及回归测试。

当前黄金样本锁定国泰君安 CTA 表 3 的八因子 × 五周期；测试确保：

- 报告日被正确识别；
- 八个因子共 40 个观察值完整提取；
- 重复导入幂等；
- 用户导出的 CSV 为周报宽表，不泄露内部审计字段。

## 提交前标准

1. 新功能至少有一个正常路径和一个边界/失败路径测试。
2. 外部周报数据必须保存来源文件、报告日、解析方式和修订版本；对用户导出隐藏这些内部字段。
3. 所有统计归因结果明确标注为估计，不表述为真实持仓。
4. 前端变更必须通过 TypeScript 检查。

## 后续增强

- 为不同机构建立独立解析器及其黄金样本；
- API 端到端测试（依赖 Windows 网络栈恢复）；
- 在 CI 中执行 `scripts/verify.ps1` 的等价命令；
- 对 OCR 结果加入字段级人工核验状态与差异告警。
