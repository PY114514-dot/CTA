# CTA 净值研究与 FOF 工作台

一个面向个人研究的本地量化研究工作台：把产品净值、SQLite 批量数据、路演材料和因子数据整理成可复核的数据资产，并完成 CTA 归因、风险评价、产品筛选、FOF 配置与人工审批跟踪。

> 本项目用于研究辅助，不构成投资建议。净值识别、策略判断、因子暴露和模型解释都必须结合原始证据与人工复核，不能视为真实持仓或管理人确认信息。

## 能解决什么问题

传统产品研究常把净值表、路演 PPT、曲线截图、策略描述与市场因子分散在不同文件里，既难比较也难复核。本项目将它们统一到产品知识库后，形成一条完整的研究链路：

```text
原始资料 / SQLite / 行情数据
        ↓
产品识别与净值复核 → 业绩与风险计算 → CTA 归因与评分
        ↓                                      ↓
产品库筛选与比较  ←────────── 研究证据与来源定位
        ↓
FOF 配置草案 → 人工确认 → 确定性评分 → 版本冻结与后续跟踪
```

## 核心能力

### 产品与数据管理

- 导入 CSV、XLS/XLSX、SQLite、图片、PDF、DOCX、PPTX 等本地资料。
- 支持期货周频 SQLite 批量导入，并可将南华商品指数等外部因子纳入因子库。
- 保存产品身份、策略标签、来源文件、页码/片段、净值候选与人工审核状态。
- 产品库区分待处理与已确认产品；已确认、净值已复核、来源可追溯的产品才能进入正式研究和 FOF 候选池。

### 净值与风险分析

- 计算累计收益、年化收益、年化波动、夏普、最大回撤、卡玛等核心指标。
- 提供净值曲线、回撤曲线、年度收益、产品对比与风险地图。
- 图片曲线识别支持裁切、取色、坐标校准和人工复核；证据不足时只保留候选，不自动写入正式净值。
- 针对不同披露日期的周频产品，FOF 组合按自然周对齐计算组合净值和组合风险收益指标。

### CTA 归因与可解释性

- 基于本地确定性计算完成趋势、期限结构/Carry、波动、市场状态、动态 Beta 和非线性增量归因。
- 支持样本内与样本外验证、滚动稳定性、因子风险贡献、CTA 风格画像和 CODEX 排名。
- 所有归因结果均保留数据范围、因子版本、样本量、适用性和局限；统计关系不被表述为真实持仓。

### FOF 配置与审批

- 从已确认、已复核产品池中按收益目标、风险上限、策略偏好和产品数量限制进行筛选与配置。
- 未指定产品数时，系统默认最多 5 只；未指定波动/回撤时，不会虚构风险约束。
- 输出产品权重、组合净值、年化收益、年化波动、夏普和最大回撤。
- 配置流程为“草案 → 人工确认 → 确定性评分 → 版本冻结 → 后续跟踪”；已通过版本保留审计记录，不能被自动覆盖。

### 受控研究 Agent

- 对话支持单产品研究、两产品比较、产品筛选、FOF 配置和已保存配置解读。
- LLM 只负责理解自然语言约束、提出必要追问和解释已算结果；不允许自行选产品、改权重、审批或执行交易。
- 工具调用通过 allow-list 校验，执行进度展示实际工具、耗时与结果。
- 会话、草案、审批决定和研究快照可保存并回看；单次 LLM 输出默认 900 token，硬上限 1200 token。

## 项目的关键设计

1. **计算与生成分离**：收益、风险、归因、筛选、权重与评分均由本地确定性代码完成；LLM 不改变数值或决策。
2. **证据优先**：每个可研究产品都关联原始文件、页码/片段、净值审核状态和数据范围，结论可回溯。
3. **人机协作而非自动审批**：LangGraph 将人工确认作为明确节点，审批前后都有可审计状态和版本快照。
4. **以 CTA 为中心的多层归因**：将风格、因子、状态依赖、动态暴露与样本外稳定性放入同一研究框架。
5. **本地优先与数据隔离**：产品数据、上传材料、SQLite 数据库、行情文件与密钥均默认忽略，不进入 Git 仓库。

## 目录结构

```text
backend/                 FastAPI、数据库模型、量化分析服务、LangGraph 流程与测试

```

## 本地安装与启动

需要 Python 3.11+ 与 Node.js 20+。

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

cd ..\frontend
npm install
```

推荐从根目录启动：

```powershell
python start.py
```

或双击 `启动.bat`。启动后访问：

- 工作台：<http://127.0.0.1:5275>
- API 文档：<http://127.0.0.1:8103/docs>
- 健康检查：<http://127.0.0.1:8103/api/health>

分别启动：

```powershell
# 终端 1
cd backend
.\.venv\Scripts\Activate.ps1
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8103

# 终端 2
cd frontend
npm run dev -- --host 127.0.0.1 --port 5275 --strictPort
```

## 可选模型配置

在应用“设置”中填写 OpenAI 兼容文本模型（如 DeepSeek、豆包、通义或 OpenAI）的 API 地址、模型和密钥。视觉模型用于图表识别，与文本 LLM 分开配置。

- 文本模型仅用于意图理解与研究解读。
- 图表识别结果必须人工核对后才能确认净值。
- API Key 写入本机 `backend/.env`，不要提交到 GitHub。

## 数据与安全边界

- `data/`、上传材料、原始 SQLite/CSV/XLS/XLSX/Parquet 文件、缓存、日志、`.env`、虚拟环境和构建产物均在 `.gitignore` 中。
- GitHub 仓库只保存可复现的代码、迁移、测试和文档；请通过应用导入本地数据，而不是提交原始产品材料。
- 使用公开仓库前仍应检查暂存区，确保没有敏感截图、客户资料、密钥或人工研究结论被误加入。
